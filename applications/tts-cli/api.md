# MiMo-V2.5-TTS API Notes

Source: `https://platform.xiaomimimo.com/docs/zh-CN/usage-guide/speech-synthesis-v2.5`

This document is a practical extraction of the MiMo speech synthesis API for implementing `tts-cli` in Go (direct HTTP API calls, no Python dependency).

## 1) Endpoint and Auth

- Base URL: `https://api.xiaomimimo.com/v1`
- API endpoint: `POST /chat/completions`
- Auth header (official examples):
  - `api-key: <MIMO_API_KEY>`

Request content type:

- `Content-Type: application/json`

## 2) Supported Models (MiMo-V2.5-TTS Series)

1. `mimo-v2.5-tts`
   - Built-in voices.
   - Supports singing mode.
   - Does **not** support voice design or voice cloning.

2. `mimo-v2.5-tts-voicedesign`
   - Voice generated from text description.
   - No built-in voice selection.
   - No singing mode.

3. `mimo-v2.5-tts-voiceclone`
   - Voice cloned from audio sample (Base64 data URI).
   - No built-in voice selection.
   - No singing mode.

## 3) Message Rules (Important)

- The text to be synthesized must be in `messages` with `role: "assistant"`.
- `role: "user"` is optional in general, used for style instruction / history.
- For `mimo-v2.5-tts-voicedesign`, `user` message is required (voice description prompt).

## 4) Audio Parameters

Payload contains an `audio` object:

- `audio.format`: output format, such as:
  - non-streaming commonly `wav`
  - streaming recommended `pcm16` (for chunk stitching)
- `audio.voice`:
  - built-in voice ID (for `mimo-v2.5-tts`), e.g. `Chloe`, `Mia`, `冰糖`
  - or Base64 data URI for voice clone model, format:
    - `data:{MIME_TYPE};base64,{BASE64_AUDIO}`

Supported clone source MIME types per doc:

- `audio/mpeg` (or `audio/mp3`)
- `audio/wav`

Voice clone data size limit:

- Base64 string must not exceed `10 MB`.

## 5) Streaming Behavior Caveat

The docs state that low-latency streaming is not yet available for MiMo-V2.5-TTS.

- `stream: true` is currently compatibility mode.
- Result is returned in streaming format only after inference is complete.

## 6) Built-in Voices (for `mimo-v2.5-tts`)

Important:

- The official docs currently provide a static voice list; no "list voices" API is documented.
- For CLI usability, `tts-cli` should expose a local static mapping so users can query model/voice compatibility from command output, without opening this `api.md`.

| 茉莉 | `茉莉` | Chinese | Female |
| 苏打 | `苏打` | Chinese | Male |
| 白桦 | `白桦` | Chinese | Male |
| Mia | `Mia` | English | Female |
| Chloe | `Chloe` | English | Female |
| Milo | `Milo` | English | Male |
| Dean | `Dean` | English | Male |

### 6.2 Model and `--voice` compatibility matrix

| Model | `--voice` rule | Example |
| --- | --- | --- |
| `mimo-v2.5-tts` | Optional; if provided, must be a built-in voice ID from table above | `--voice Chloe` |
| `mimo-v2.5-tts-voicedesign` | Not required; voice is generated from `--user-text` description | (usually omit `--voice`) |
| `mimo-v2.5-tts-voiceclone` | Required; must be data URI: `data:{mime};base64,{audio}` | `--voice data:audio/mpeg;base64,...` |

### 6.3 CLI discovery requirement (implementation note)

To avoid requiring users to read `api.md`, `tts-cli` should provide a discovery command, for example:

- `tts-cli capability list_models`
- `tts-cli capability list_voices`

Expected output should include at least:

- supported models
- per-model `--voice` rule
- built-in voice IDs for `mimo-v2.5-tts`

## 7) Minimal Request Templates

### 7.1 Built-in Voice (non-streaming)

```json
{
  "model": "mimo-v2.5-tts",
  "messages": [
    {
      "role": "user",
      "content": "Speak in a bright, upbeat tone and slightly faster pace."
    },
    {
      "role": "assistant",
      "content": "Hello, this is a demo generated by MiMo-V2.5-TTS."
    }
  ],
  "audio": {
    "format": "wav",
    "voice": "Chloe"
  }
}
```

### 7.2 Voice Design (non-streaming)

```json
{
  "model": "mimo-v2.5-tts-voicedesign",
  "messages": [
    {
      "role": "user",
      "content": "Young male voice, warm and clear, medium speaking speed."
    },
    {
      "role": "assistant",
      "content": "This is a voice design synthesis sample."
    }
  ],
  "audio": {
    "format": "wav"
  }
}
```

### 7.3 Voice Clone (non-streaming)

```json
{
  "model": "mimo-v2.5-tts-voiceclone",
  "messages": [
    {
      "role": "user",
      "content": ""
    },
    {
      "role": "assistant",
      "content": "This is a voice cloning synthesis sample."
    }
  ],
  "audio": {
    "format": "wav",
    "voice": "data:audio/mpeg;base64,BASE64_AUDIO_HERE"
  }
}
```

### 7.4 Streaming Mode Example

```json
{
  "model": "mimo-v2.5-tts",
  "messages": [
    {
      "role": "user",
      "content": "Speak naturally and calmly."
    },
    {
      "role": "assistant",
      "content": "This is a streaming output sample."
    }
  ],
  "audio": {
    "format": "pcm16",
    "voice": "Chloe"
  },
  "stream": true
}
```

## 8) Response Handling Notes for Go CLI

For non-streaming calls:

- Parse OpenAI-compatible response from `/chat/completions`.
- The synthesized audio is provided in Base64 (field path shown in doc examples as `choices[0].message.audio.data`).
- Decode Base64 and write to output file (`.wav` or other requested format).

For streaming calls:

- Parse SSE chunks.
- Collect chunk audio data (`delta.audio.data` per chunk), Base64 decode, append bytes.
- For `pcm16`, stitch chunks in order and write as raw PCM or convert to WAV wrapper in CLI.

## 9) Style Control Summary

Two control methods are documented:

1. Natural language control
   - Put style instruction in `user.content`.

2. Tag control
   - Put style tags directly in `assistant.content`, e.g. `(singing)` prefix.

Singing notes:

- Add `(唱歌)` / `(sing)` / `(singing)` at the beginning of synthesized text.
- Mainly documented for `mimo-v2.5-tts`.
